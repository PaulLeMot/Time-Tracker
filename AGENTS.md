# Правила совместной разработки ОперПортала

Утверждены владельцем27.10.2026. Единственная рабочая ветка — main.

Перед любым изменением, включая документацию: git status; git fetch origin;
git switch main; git pull --ff-only origin main. Сначала убедиться, что рабочая
папка чистая; чужие изменения не удалять и не прятать автоматически.
Синхронизация обязательна при каждом новом задании. При ошибке сначала
выяснить причину; не редактировать устаревшую копию.

Не создавать дополнительные ветки или Pull Request без прямого разрешения.
Изучать актуальный код, делать локальные правки, сохранять изменения соавторов.
Не применять force push, reset --hard, clean -fd. В коммит добавлять только
проверенные файлы задачи поимённо. Перед публикацией изучить diff и выполнить
необходимые тесты. После локального коммита: git fetch origin;
git pull --rebase origin main; повторные проверки при изменении кода;
git push origin main. Не обходить защиту ветки. При конфликте сохранять чужую
работу; если безопасное разрешение неясно — сообщить владельцу.

Сервер обновлять только из origin/main после успешных тестов и push.
Проверить чистоту сервера; git fetch origin; git switch main;
git pull --ff-only origin main. После установки HEAD должен совпадать с
origin/main. Не устанавливать отдельные ветки, незакоммиченный код или коммиты,
которых нет в origin/main. Для Docker использовать актуальный код main;
секреты, переменные окружения, базы и пользовательские файлы сохранять.

В отчёте: ветка и первоначальная синхронизация, изменённые файлы, тесты,
SHA коммита, результат push в main, факт установки и SHA сервера.
