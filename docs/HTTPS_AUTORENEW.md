# HTTPS: продление сертификата локального ОперПортала

Имя operportal.fandocraft.ru:8443, существующий nginx operportal-https и
существующий Certbot5.9.0; не перезапускать приложение, его CMD содержит migrate.
Скрипты deploy/https используют только stdlib и прежний image с закреплённым
sha256. Выпуск выполняется DNS-01; новые входящие порты не нужны.

SpaceWeb не ограничивает дополнительного пользователя отдельным доменом/TXT.
Владелец отдельно подтвердил пользователя только с разделом «Мои домены»,
охватывающим DNS всех доменов аккаунта. Основной пароль не переносится.
Credential JSON с login/password размещается владельцем в
~/.local/share/operportal-https/private/spaceweb.json, каталог0700/файл0600.
Секреты и токены не входят в Git/командную строку/статусы. Удаление этого
пользователя в панели немедленно отзывает доступ и прерывает продление.

Hook допускает только operportal.fandocraft.ru и TXT
_acme-challenge.operportal.fandocraft.ru. Сохраняет intent до записи,
ожидает значение на четырёх авторитетных NS, удаляет только собственное
значение по актуальному индексу TXT. Чужие записи, включая одноимённые TXT,
не заменяет. Индексы могут перенумеровываться; имя+тип+значение проверяются.
Незавершённая запись остаётся в закрытом renewal-state для восстановления.

Первичная настройка из опубликованной main:

1. Сохранить копию renewal config, TLS и crontab; проверить владельца каталогов,
   прежний production fingerprint и чистоту Git сервера.
2. От имени существующего Docker-владельца выполнить
   python3 deploy/https/renew_https.py --reconfigure. Certbot сначала проверяет
   DNS-01 на staging и только при успехе сохраняет автоматические hooks.
3. --deploy-check проверяет production chain/SAN/ключ/остаток>=30суток,
   безопасную публикацию и nginx-t + graceful reload с проверкой выдаваемого
   fingerprint. Ошибка восстанавливает обе старые TLS-копии и reload.
4. Установить именованный блок пользовательского crontab: два раза в сутки
   запуск того же опубликованного скрипта. Системный cron должен быть enabled
   и active; привязка к графическому входу/lingering не нужна. Сохранять чужие
   строки crontab. Один процесс защищён flock, таймаут DNS20мин/Certbot30мин.
5. Проверить --dry-run и обычный renew, отсутствие оставшейся TXT, неизменность
   прочей зоны, last-attempt/last-success, HTTPS с доверенной цепочкой.

Корень состояния ~/.local/share/operportal-https: certs, certbot-work,
certbot-logs, private, renewal-state, tls. Hook монтируется read-only из
deploy/https опубликованного checkout; credentials read-only; Docker без
capabilities/no-new-privileges, UID существующего владельца. Certbot ведёт
свои логи; журнал запуска и статус находятся в закрытом renewal-state.
В status нет пароля/токена/кадров; есть время, режим, fingerprint и результат.
last-success сам по себе не доказывает доступность DNS: нужен staging тест.

Откат: убрать только управляемый cron-блок, сохранить диагностику; вернуть
preimage renewal config и прежние два TLS-файла, nginx-t, затем reload и
проверка HTTPS. Не удалять рабочие сертификаты, данные, контейнеры и аккаунт
Certbot. При отмене автоматизации отозвать технического пользователя.

Тесты lab/test_https_renewal.py: чужие/существующие/дублирующиеся TXT,
