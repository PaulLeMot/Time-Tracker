## Поведение

Обе прежние кнопки «Камера» в поиске изображений и маркировке используют один
диалог и прежние API/renderer. Ручной ввод, аппаратный сканер, фильтры и история
сохраняются. Требуется доверенный HTTPS; HTTP8000 продолжает обслуживать ручной путь.

- Захват строго с `facingMode.exact=environment`, audio=false. Передняя камера не
  предлагается. Другую заднюю можно выбрать только по распознанной rear-метке;
  после разрешения сохраняется лишь deviceId в памяти страницы. При устаревшем ID
  один повтор без deviceId, но по-прежнему с обязательной задней камерой.
- Непрерывный автофокус запрашивается при его поддержке. Подсветка и масштаб1–3×
  показываются только при наличии capabilities. Точное минимальное увеличение
  определяется устройством. Фокус по касанию включается только при поддержке
  pointsOfInterest и single-shot; иначе работает штатная фокусировка телефона.
- Область внутри рамки соответствует реальному участку исходного видео с учётом
  object-fit/полей. Каждый четвёртый проход берёт весь кадр. Разрешение до1920px,
  контраст и инверсия используются дозированно; небольшой код не уменьшается
  безусловно до старого размера всего кадра. Нет очереди устаревших кадров.
- Локальный ZXing-C++ WASM в отдельном Worker читает EAN-13/Code128, включая
  поворот; native BarcodeDetector применяется, только если доступен с нужными
  форматами. Резерв — прежний локальный ZXing-JS в Worker. Целевой интервал100мс,
  один decode одновременно. Несколько различных кодов в ROI требуют навести на один.
- Режим «Артикул в тексте» включается явно. Локальный Tesseract LSTM читает цифры
  и латинские артикулы среди текста. Два последовательных чтения с confidence≥35
  должны иметь общий кандидат. Затем камера остановлена, поиск выполняется
  прежними точными API, а пользователь **обязательно** подтверждает код и название
  до показа картинки/результата. «Не подходит» сохраняет прежний результат.
- Извлекаются отдельные пятизначные коды, составные артикулы с пятизначной группой
  и полные числовые ID. Начальные нули сохраняются. Не более6 кандидатов, не более
  1500символов текста. Пятизначные подстроки длинных цифровых ID не извлекаются.
  Для распространённого O+5цифр допускается только узкий вариант путаницы O/0:
  ровно0+5цифр непосредственно после SKU/article/артикул/арт./код. Исходное чтение
  и предупреждение видны в подтверждении. Общей нечёткой замены символов нет.
- Марка и площадка учитываются прежним endpoint маркировки. Прямой внутренний
  FSK-код из пяти цифр универсален так же, как внутренний EAN; похожие стикеры не
  выбираются автоматически. Ошибка источника/доступа отменяет всю OCR-выдачу.
- Закрытие, Escape, Back, background, pagehide, смена режима/камеры и ошибки
  освобождают собственные tracks, Worker, canvas, timers и frame callbacks.
  Поздний результат не вызывает поиск. Инициализация Worker тоже отменяется сразу.

## Приватность и зависимости

Кадры остаются в RAM: canvas→ImageData→barcode Worker либо PNG ArrayBuffer→OCR
Worker. Последний использует виртуальную RAM-файловую систему WASM. Фото/видео
не сохраняются, не скачиваются и не отправляются на сервер/внешний сервис.
В сеть передаются только считанные строковые кандидаты в прежних GET API.
OCR `cacheMethod=none` исключает IndexedDB; HTTP-кэш библиотек/языковой модели
допускается. История маркировки хранит лишь подтверждённый код, не полный текст.
Метрики в памяти содержат время/число кадров/название движка, без кодов и кадров.

Новые файлы поставляются с портала без CDN: zxing-wasm3.1.6 (~1МБ), worker
tesseract.js6.0.1, core6.1.2 (baseline/SIMD LSTM), eng1.0.0 traineddata.
OCR загружается только при выборе текстового режима (~7МБ выбранных ресурсов).
Полный набор обоих core-вариантов и лицензий занимает около12МБ. OEM1 фиксирован;
прямой адаптер официального worker-протокола6.0.1 позволяет отменить загрузку
немедленно. При обновлении версии адаптер требует повторной проверки.
Версии, npm SHA512 и SHA256 каждого артефакта: `static/vendor/camera-1.1-dependencies.lock.json`.
Атрибуция: `static/vendor/CAMERA-1.1-NOTICES.txt`. OSV не вернул известных advisory
для четырёх проверенных npm-версий на дату проверки; это не полный аудит нативных
транзитивных компонентов.

собирать в отдельной чистой локальной main-копии после fetch/ff-only. Публиковать

resolver/CSS, два HTML, синтетические проверки и документация. После каждого push
на сервере clean→fetch→switch main→pull --ff-only; HEAD=origin/main. Проверить
HTTP/HTTPS-хэши, вход, безопасный malformed JSON redirect, неизменность ID,
StartedAt/RestartCount контейнеров и HTTPS-конфига. Не вызывать restart/rebuild,
refresh/import/миграции/реальные отметки. Итоговые SHA и доказательства фиксируются
в сопровождающем отчёте выпуска, а не угадываются заранее.
