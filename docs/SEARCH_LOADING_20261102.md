## Выяснено

Read-only GET на старом сервере:filtered API30 товаров —HTTP125–140мс,
HTTPS161–182мс; первая проверенная категория14.5/63мс. Четыре проверенных JPEG
размером16–18KiB —HTTP4.7–7.3мс,HTTPS47.9–70.9мс с новым TLS-соединением на
каждый запрос. На момент замера appCPU0.77%,RAM252MiB/1GiB. Это короткая выборка
из серверной среды, не измерение реальных телефонов/Wi-Fi и не полный профиль БД.
Многосекундный server stall этой выборкой не воспроизведён.

В текущем клиенте воспроизведены конкретные причины ожидания/остановки:

- Выбор вида/фандома ждал refresh вариантов фильтра, затем начинал товары;
  при ошибке options товары вообще не запрашивались. Старый options-ответ мог
  перезаписать варианты после нового выбора.
- Sentinel имел нулевую высоту и нулевой запас IntersectionObserver:запрос только
  у самого конца, без подготовки следующей страницы. При видимом sentinel во время
  запроса и коротких порциях мог не появиться новый intersection edge.
- Все30 картинок eager/default одновременно, без async decode. На HTTPS/ограниченных
  соединениях телефона это лишняя конкуренция с видимыми изображениями и API.
- Между вводом кода и400мс reset observer мог запросить новый код со старым offset.
  Пустая страница при несогласованном total оставляла hasMore активным.

Не утверждается, что все эти места внесены именно последним выпуском камеры:
это воспроизведённые дефекты текущей страницы, которые усиливают сетевую задержку.

## Исправление

Только static/search.html:товары и options загружаются независимо, options имеют
AbortController+generation. Результаты фильтра не ждут варианты и не пропадают
из-за их ошибки. Старый options-ответ не меняет новый выбор.

Порция по-прежнему30; заранее загружается ближайшая следующая порция в пределах
600–1600px (до двух экранов), не весь каталог. Sentinel1px, IntersectionObserver
rootMargin, rAF-проверка после ответа/scroll/resize восполняют потерянный edge и
заполняют короткий viewport. Один in-flight, прежние offset/total; пустая страница
останавливает цикл. После ошибки есть «Повторить загрузку» с тем же offset и
сохранением уже показанных карточек.

Первые6 изображений eager, остальные native lazy, decoding=async; карточки
добавляются одним DocumentFragment. Размеры/источники/качество картинок сохранены;
число реально скачиваемых lazy-файлов определяет браузер, оно не фиксировано6.
Новый ввод приостанавливает пагинацию до reset; при отмене/неуспехе barcode
предыдущая пагинация возобновляется. pagehide останавливает запросы, pageshow
persisted восстанавливает пагинацию без стирания результата/фильтра.

Backend/Python runtime, SQL, БД, nginx/TLS, изображения, mark.html, логотипы,
Next и новый photo-service не менялись. Полные фото каталога не выгружались.
