## Поведение и переиспользование

В `/static/search.html` (переход «Поиск изображений» из ЛК) и `/mark`
добавлена кнопка «Камера». Видеопоток запускается только по нажатию,
без звука, с предпочтением задней камеры. Общий диалог работает в текущем
Vanilla JS, без нового фреймворка или переноса глобальных стилей ОперКонтура.
Старые поля, очистка, история, фильтры, пагинация и renderer маркировки используются
повторно. Для новых элементов один scoped CSS и native dialog.

`static/camera-scanner.js` владеет только своими tracks, canvas, decode-loop
и обработчиками. Нет транспорта, записи кадров, blob/data URL, localStorage,
upload и телеметрии. Целый кадр уменьшается максимум до1280×960, без обрезания
длинного штрихкода; следующий проход начинается через200мс после предыдущего.
После результата поток остановлен **до** вызова адаптера. Закрытие, Escape,
Back/navigation, pagehide, background, ошибка и тайм-аут30сек освобождают ресурсы.
Позднее разрешение после отмены сразу останавливается. Повторный запуск — кнопкой.

`static/camera-code-search.js` проверяет формат, алфавит и размер строки (5–128),
контрольную цифру EAN13, сохраняет начальные нули, не открывает URL и не удаляет
разделители GS1 произвольно. Строка передаётся в существующие API с credentials
same-origin. Новых endpoint/прав/записей/миграций нет.

- Маркировка: один GET `/api/mark/{code}?marking=...`, текущая марка/площадка
  учитывается. Существующий backend читает XLSX/CSV и выполняет все соответствия;
  новая таблица/дубликат алгоритма не создавались. Camera не вызывает refresh.
  Похожие стикеры (`similar_sticker_match`) остаются предупреждениями, а не
  кандидатами товара. При нескольких точных товарах — явный выбор, затем прежний
  `renderResults`, одна запись кода в прежнюю историю. Ручной путь/его regex сохранены.
- Изображения: точный существующий `/api/products/{canonical}`; для внутреннего
  EAN `2400000` с корректной контрольной цифрой применяется известный срез[7:12].
  При отсутствии прямого товара используется тот же GET маркировки, затем точный
  каталог для выбранного canonical code. Камера не использует substring-выдачу;
  ручной частичный поиск сохранён. Это до трёх последовательных GET для marketplace,
  а не запросы на каждом кадре. Ошибка/отмена сохраняют прежний список и ввод.
- Если найденный товар скрыт видом/фандомом, показана причина и отдельная кнопка
  снятия **только мешающих** фильтров. Сами фильтры не сбрасываются.
- Generation и AbortController защищают оба экрана от поздних ответов.
  Ручной Enter в поиске картинок отменяет debounce и выполняет один поиск.
- 0 — понятное сообщение,1 — результат,N — выбор. Источник недоступен,
  отсутствие товара, завершённый сеанс и сетевая ошибка различаются.

## Зависимости и ограничения

Локальный официальный UMD `@zxing/library@0.23.0`, Apache-2.0,362150байт.
Используется `MultiFormatOneDReader` только с EAN_13/CODE_128.
Это осознанный выбор вместо browser-camera wrapper: жизненным циклом управляет
портал, а библиотека только декодирует память. Native BarcodeDetector не нужен.
Официальный bundle закреплён SHA256, исходный npm-архив — SHA512. Никакого
плавающего npm resolution/build/CDN в рабочем браузере или на сервере.
Встроенные helper-коды закреплены полным hash bundle; отдельно runtime-зависимости
не разрешаются. Upstream объявляет ts-custom-error^3.3.1; его MIT notice также
поставляется. Точный состав артефактов — `static/vendor/camera-dependencies.lock.json`.
Вспомогательный воспроизводимый загрузчик поставлен отдельно от runtime checkout.

Библиотека грузится по требованию при первом открытии камеры. Ошибка загрузки
не мешает ручному вводу. На HTTP LAN камера недоступна: диалог объясняет необходимость
HTTPS и оставляет ручной способ. Требуются современный браузер, native dialog,
getUserMedia и доверенный secure context. Версии личных телефонов ещё не проверены.

Код маркетплейса найдёт товар только при наличии точного соответствия в текущих
рабочих выгрузках. Метаданные файлов используются прежним backend по его правилам
даты/марки. Новый decoder не обещает распознать все возможные этикетки, отправления,
последние4цифры или код без соответствия. QR из исходного handoff исключён по
последующему уточнению владельца.

Существующие страницы светлые; новая глобальная тема не добавляется. Геометрия
новых элементов проверяется на360/390/430px, landscape844px и desktop1366/1920,
обычном/увеличенном тексте. Это browser emulation, не настоящие телефоны.

## Проверки и отдельная лаборатория

`node --test test_camera_search.cjs` — синтетические контракты resolver.
`python -B -m unittest test_operkontur_images_sync.py` — прежний обмен без запуска.
`lab/index.html` и `lab/tests.js` — проверка фактических страниц с подставным API,
fake media и настоящим decoder на PNG, независимо созданных ReportLab.
Лаборатория запускается внешним `camera_lab.py` из корня отдельной копии исходников
и слушает только127.0.0.1. Она не импортирует main/database, не имеет production
credentials, не проксирует запросы и отвергает POST. Штатный Docker/startup не запускать.
Фикстуры явно синтетические. Точный протокол и hashes — в пакете кандидата.

Вспомогательные Python-файлы намеренно **не входят в Git-кандидат TimeTracker**:
uvicorn --reload может отреагировать даже на новый инструмент .py внутри `/app`.
В рамках установки камеры не нужны сборка, restart, migrate или изменение службы.

## Два входа в одно приложение

- Старый HTTP: `http://192.168.137.105:8000` — сохранён, без редиректа.
- Новый HTTPS: `https://operportal.fandocraft.ru:8443` — тот же backend8000,
  та же БД. Камера требует именно этот доверенный HTTPS-адрес.

На SpaceWeb добавлена только A-запись operportal ->192.168.137.105.
Временная TXT-запись DNS-01 после выпуска удалена. Записи основного сайта
и почты сохранены. Nic.ru не менялся. Публичный DNS содержит частный адрес,
поэтому портал по-прежнему требует доступа к локальной сети. На телефоне
с защищённым DNS/защитой от DNS rebinding разрешение имени может потребовать
отдельной диагностики; обход предупреждений сертификата не является решением.

Отдельный nginx1.30.6, контейнер operportal-https, проксирует все пути на
127.0.0.1:8000, слушает только192.168.137.105:8443. UFW дополнен одним правилом:
enp7s0, источник192.168.137.0/24, назначение192.168.137.105 TCP8443.
Старые правила сохранены. HSTS, redirect8000, внешний туннель, проброс
маршрутизатора и общие службы не добавлялись. Перезапуск — unless-stopped;
read-only FS, uid1000, cap-dropALL, no-new-privileges, ограничения CPU/RAM.

## Продление: ручное, автоматизация ещё не завершена

Планировщика автоматического продления нет. Первичный certbot manual hook
создавал новую TXT-задачу и ожидал оператора; это не автономная интеграция
с DNS. Старое подтверждение dns-ready удалено. Не запускать periodic renew
с этим hook, не объявлять автопродление работающим без end-to-end dry-run.
Основной пароль SpaceWeb и cookies панели на локальный сервер не переносились.
С разрешения владельца в SpaceWeb отправлено обращение2026110210031394:
доступ к DNS-01 только для этой записи/зоны и возможность его длительного
автоматического использования. Ответ ещё не получен; пользователей/токенов
в SpaceWeb для автоматизации этой задачей пока не создано.

До завершения автоматизации обслуживающий инженер должен начать продление
не позднее начала января2027. Оно бесплатно, требует новой проверки DNS-01:
новая TXT-запись в SpaceWeb, проверка авторитетных NS, выпуск через существующий
ACME account, проверка имени/цепочки/срока и соответствия закрытого ключа.
Старый рабочий сертификат до успеха сохраняется. Затем обновить оба PEM-файла
в leaf-каталоге tls с правами0600/uid1000, выполнить nginx -t в отдельном
контейнере с теми же mount и image; только при успехе — graceful HUP новому
operportal-https. Проверить новый отпечаток/срок с другого LAN-устройства
обычной проверкой TLS. Старый app и БД не перезапускать. Одного обновления
PEM-файлов без reload недостаточно. Ручной процесс требует инженера;
этот документ не заменяет отсутствующий проверенный механизм автопродления.

## Приёмка на телефонах и откат

Подключить телефон к рабочему Wi-Fi, открыть HTTPS-адрес, войти обычной
учётной записью. Доверие должно быть без предупреждений и установки CA.
В поиске изображений и маркировке проверить по10 EAN13/Code128, правильный
товар и существующие marketplace mappings. Проверить закрытие, повторное
открытие, отказ доступа, фон/блокировку, ручной ввод и аппаратный сканер.
Камера запрашивается только явным нажатием; фото не сохраняются и не уходят.
Физические Android/Яндекс/iPhone пока не проверены. QR не включён.

Откат камеры: fresh clean main -> обычный git revert HTML-коммита B ->
проверки -> fetch/pull --rebase/push origin main -> server clean/fetch/switch
main/pull --ff-only. При соавторских изменениях сохранять их, конфликт не
решать автоматическим reset. Assets A оставить для уже открытых вкладок.
Если требуется убрать HTTPS, остановить только контейнер operportal-https;
HTTP8000 продолжит работать. Затем можно удалить ровно добавленное UFW-правило
с комментарием operportal-https-lan и нашу A-запись. Сертификаты/закрытые ключи
не удалять до завершения отката. Не восстанавливать БД, не делать force/reset,
не останавливать app/DB или соседние проекты.
